Not every change needs a human. Some need two.

Anthropic shared how the Claude Code team reviews code now that Claude writes about 90% of it. The key move: sort every change by risk, and spend human attention where mistakes cost the most.

Oct 23, 2026 Interactive diagram ↓ Sources ↓ Follow on LinkedIn ↗
The short version
  • Claude writes about 90% of Claude Code's own code, so the team sorts every change by risk: 0, 1 or 2 human approvers.
  • The work is verified before anyone else looks, and after 3 review rounds the reviewer asks the author to rethink the approach.
  • June to September: merged PRs more than doubled while the share that had to be reverted fell by more than 40%.

Why review had to change

Across Anthropic's monorepo, changes landing per day went from about 2,500 in May to more than 30,000 in September. Claude Code lives in its own repo but feels a lot of that pressure too, and line-by-line human review at that pace is close to impossible. So they named the scarce resource: human time and attention. They track human approvals per PR, human comments and how long a PR waits on a person, with revert and incident rates as the guardrail.

Review now runs continuously, "more like spellcheck while you write," across seven layers:

  1. The work is verified before anyone else looks
  2. AI review on every pull request
  3. Security review that can block
  4. Automated checks that block
  5. Human approval, scaled by risk
  6. Merge queue, flags and a gradual release
  7. Fast detection, fast rollback

The tiers

RiskExamplesHuman approvals
LowDocs, copy, internal-only features, additive changes behind a flagNone, once automated review and security checks are green
MediumOrdinary product changes, and sensitive areas like caching, the auto-updater or system promptsOne person
HighThe highest-risk code, plus a small set of paths that always need two peopleTwo people
"The change sets the tier, not the author."How the Claude Code team does code review, Oct 15, 2026

A classifier reads the change and picks its risk tier, so nobody gets to talk their own change down to "low." Two more rules keep the light paths honest: only authors on the repo's trusted list (mostly the team that owns it) get them, and an agent's approval never counts as a person's.

Verified before anyone looks

Their first layer is the one to copy. Give the agent something it can run (tests, a build, a screenshot to compare against the design) and ask it to show the output instead of saying it's done. Then a subagent reviews the diff with fresh context.

Per the post, Boris Cherny estimates that giving Claude a way to verify its work makes the final result two to three times better. Claude Code's best-practices guide says it directly: without a check it can run, "looks done" is the only signal available, and you become the verification loop.

When review won't settle

After three rounds, the reviewer asks the author to step back and reconsider the approach. With that cap and a few related rules, internal PRs settled in fewer rounds:

65% → 78%passed after one review-and-fix round
8.9% → 1.5%needed five or more rounds
2.08 → 1.32average reviews to pass

The headline result: from June to September, merged pull requests more than doubled while the share that had to be reverted fell by more than 40%.

Block does it at migration scale

Block shared a similar setup on Oct 8. In any given migration they might merge about a thousand pull requests orchestrated by Claude Fable, which directs up to dozens of smaller models like Opus or Sonnet for the individual tasks. Agent changes have to pass security checks, then two humans approve the deploy: a dual-approval layer, so no model pushes those changes alone.

Why tiers work

Approve everything and the clicks stop meaning much. Claude Code's own guide says it about permission prompts: "After the tenth approval you're clicking through rather than reviewing." Tiers save human attention for the changes where it counts.

The same idea, scaled down

My personal AI setup runs three tiers:

ActionWhat happensWho approves
Edits to my own filesJust runNobody
Drafts, like emailsGet written, then waitMe, before anything goes out
Sends to anyone but meNeed my yes; in the most hands-off mode a hook blocks them outrightMe, every time
